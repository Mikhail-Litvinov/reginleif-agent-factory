# Agent Factory: modules, files, interfaces, migrations, risks

Binding: [architecture.md](architecture.md). Tables: [database.md](database.md). Workflow: [temporal.md](temporal.md).
Interface: [api.md](api.md). Adapters: [agent-adapters.md](agent-adapters.md). Checks: [testing.md](testing.md).
Security: [security.md](security.md). "Spec 4.2" is a section of the task specification. "Call" is a choice made here,
open to veto. Paths: `F/` is `factory/` (own package, Node 24, D1 D2 D17); `R/` is the Rig repository (Bun).

## Phase 0 (this folder)

Design documents, plus proofs S1-S6 (testing.md). The proofs are throwaway code in the scratch area, not part of the
tree. S2 and S4 are proven. What the proofs leave open becomes tests in phase 4 (see Phase 4, Proving check): a foreign
process with the same pid, a pruned `rig exec` record, a crash before `identity.json` is written, a starter killed
without its tree. S1, S3, S5 and S6 are proven in the phase that builds on them (S6 in phase 1 against the real
proxy, with the D28 part that the trial did not cover).

## Risks

| Risk | Mitigation | Phase | Proof |
|---|---|---|---|
| Worker restart loses a running agent | Runner outlives worker; marker and exit file | 4 | F7-F9 |
| Duplicate start after retry | Intent file first, execution id, lookup table | 4 | F8 |
| Forged workflow update | Updates carry only a decision id; mTLS plus method allowlist | 3 | `wf-forged-update`, S6 |
| Forged answer to a server step | Server steps never enter a queue (D28) | 3 | `control-no-queue`, S6 |
| Forged result of another machine | One machine until the gateway exists (D28) | 2 | `second-machine-refused` |
| Same-user agent reads secrets | Env allowlist, profiles (D13 accepted risk) | 4 | `env-allowlist`, `secret-canary` |
| Double press of a destructive button | Second-press confirmation, button replay refusal | 2, 6 | `second-press`, `button-replay` |
| Migration breaks a running release | Expand then contract, checksums, advisory lock | 2 | migration test on a copy |
| Lost notices with the PC off | Server side outbox; open until a server exists | 6 | none before a server |
| Reviewer shares provider with implementer | Hard filter in SelectAgent plus trigger | 3, 5 | `review-provider` |
| Check reported passed without a run | Stored run_checks record wins; D26 | 4 | `check-not-run` |
| GPU contention | Lease table, no preemption | 5 | `gpu-order` |
| Codex limit or orphan restarts | Reactive `limit` status, restart switch in codex-run.py | 4 | F10 |

## Not reachable before a server exists

Permanent operation, work while the PC is off, external TLS, off-host backups, real network loss on hardware,
failure notices with the PC off (D5). Until then these stay open items in every phase report.

## Verification done

- Tables: 28 tables in database.md (`outbox_events` and `execution_policies` counted once). Migrations 0001-0006 hold
  9+3+6+5+4+1 = 28 tables. Each of the 27 first-column names plus `task_transitions` appears in exactly one migration row,
  compared by name.
- Phase deliverables: every spec phase 1-7 criterion has a module row and a proving check above. The Rig change list
  (feature, command, installer, autostart, codex-run.py) is fully assigned to phase 4, with the audit items (the five
  `cli.ts` places, fixture, message catalogues, repository scans, installer test copy list).
- Holes found and closed in this pass: the coverage table was invented and wrongly numbered, with no subsections; the
  proofs sat in the tree; plain SQL contradicted D27; the foreign key cycles and `origin_run_id` were unhandled;
  notification values were unnamed and the table came after the phase that needs it; metrics and structured logs had no
  home and no route; the audit items for Rig and Temporal were missing.
- Still open: see "Not reachable before a server exists"; the button mechanism of the hub fork; the notice repeat interval (phase
  6); the proof cases listed in phase 4; the Drizzle claims (checksum behaviour of the migrator, deferrable keys
  through `drizzle-kit`) until phase 2 runs them; the metrics route has no check yet.
